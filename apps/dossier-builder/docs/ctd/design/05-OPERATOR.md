# 05 — Claude جوّه الأداة: المشغّل (Operator)

**الحالة:** تصميم مقترح، 8 نوفمبر 2026. يبني على 01-PLAN و02-LOGIC و04-REVIEW. لم يُبنَ منه شيء بعد إلا المرحلة M0 (التشغيل من جلسة Claude Code على المحرك، مُجرَّب على ملف Wouncure).

## 1. الفكرة في سطرين

المحرك (`dossier_engine`) هو المرجع: البيانات، الملفات، النسخ، سجل التدقيق، الشروط المذكورة بمصدرها، كتابة eCTD، الفحوص، والمراجعة بالقواعد. Claude هو المشغّل: يقرأ المستندات بفهم (نص وصور)، يملأ البيانات عن طريق أدوات المحرك، يقرر في أسئلة المراجعة المفتوحة ويكتب الردود، ويطلب من المحرك التوليد والتصدير. لا يكتب Claude XML ولا يحسب checksum ولا يغيّر دليلًا من طرف ثالث؛ وكل ما يفعله مسجَّل باسمه وبسببه، ومعلَّق على اعتماد إنسان في القرارات الحاسمة.

## 2. لماذا طبقتان وليس «كلام مع Claude» فقط

| الاحتياج | المحرك | Claude |
|---|---|---|
| نفس الناتج كل مرة، وقابل للتحقق (XML صالح، checksums، 226 سؤال مراجعة، 150 شرط) | نعم | لا |
| حالة تعيش أسابيع (نسخ، تدقيق، تعليقات، مهل زمنية) | نعم | سياق مؤقت |
| قراءة مستند ممسوح بفهم، ومقارنة مواصفة بدستور أدوية، والحكم على كفاية تبرير | ضعيف (قواعد) | نعم |
| صياغة ردود على استفسارات الهيئة بلغة المقيّم | قوالب | نعم |
| العمل بدون إنترنت وبدون تكلفة لكل عملية | نعم | لا |

النتيجة: واجهة أدوات واحدة من المحرك (MCP)، يستخدمها Claude من أي مضيف. الواجهة الرسومية الحالية تبقى كما هي، ويُضاف إليها لوحة «المساعد» في مرحلة لاحقة.

## 3. المعمارية

```
المستخدم ──► مضيف Claude ──(MCP stdio/HTTP)──► dossier-mcp ──► FastAPI engine ──► SQLite + ملفات
              │ Claude Code / Desktop                      (نفس الدوال، نفس الصلاحيات)
              │ أو لوحة «المساعد» في الأداة (Agent SDK)
              └─ يقرأ صور الصفحات عبر أداة page_image أو أداة Read المدمجة
```

- `dossier-mcp`: خادم MCP صغير (Python، حزمة `mcp`/FastMCP) داخل `dossier_engine/mcp_server.py`، يلفّ نقاط الـ API الحالية (54 نقطة) في نحو 25 أداة مكتوبة بوضوح، ويعمل على نفس مساحة العمل التي تستخدمها الواجهة.
- لا منطق جديد في الخادم: كل أداة تستدعي دالة المحرك الموجودة، فما تفعله الواجهة يفعله Claude ولا أكثر.
- كل استدعاء يُسجَّل في `audit` بـ `actor = "claude"` ومعه `rationale` (نص قصير يكتبه Claude مع كل تغيير).

## 4. سطح الأدوات (MCP)

**قراءة (بدون آثار):**
- `dossier_list()`، `dossier_get(did)`، `board(did)` (الفتحات وحالتها والشرط وراء كل فتحة بمصدره)
- `slot_requirement(did, slot)` (النص المطلوب، المرجع، ما يُقبل كدليل)
- `data_get(did)` (المواد الفعالة، التشغيلات، المواصفات، النتائج، التركيب، التسجيل)
- `document_text(did, doc_id, pages)` و `document_page_image(did, doc_id, page, dpi)` ← ترجع صورة الصفحة كمحتوى صورة، فيرى Claude الصفحة نفسها حتى لو السكان بلا نص
- `review_pack()`، `review_get(did, rid)`، `review_evidence(did, rid, fid)` (المقتطفات والصفحات التي وجدها المحرك)
- `audit(did)`، `gate(did)` (لماذا التصدير محجوب)

**كتابة (مسجَّلة، بعضها يحتاج اعتماد):**
- `dossier_create(profile)`، `profile_set(did, …)`، `data_put(did, data, rationale)`
- `document_upload(did, slot, file, validity, signed_for, rationale)`، `document_withdraw/restore`، `document_fix(did, doc_id, kind)` (الإصلاحات المسموحة فقط؛ قفل الطرف الثالث يبقى)
- `classify(did, files)` ← اقتراحات، والوضع الفعلي عبر `document_upload`
- `generate(did, kind, inputs)` (المولدات الموجودة: Annex I، التركيب، خطاب التغطية…)، `generate_prefill`
- `review_run(did, options)`، `finding_act(did, rid, fid, action, note)` (confirm | override | withdraw | reopen | dismiss_ai)، `response_add`، `reassess`، `review_letter`، `review_report`
- `request_letter(did, slot, reason)` (طلب إعادة إصدار من الجهة)
- **تحتاج اعتماد إنسان دائمًا:** `export(did, …)`، `review_sign(did, rid)`، `document_withdraw` لأدلة الطرف الثالث.

**موارد (Resources) للقراءة السريعة:** `dossier://{did}/board`، `dossier://{did}/documents/{doc}/page/{n}`، `pack://review/{dept}`.

## 5. أين يعمل Claude

| المضيف | ما يراه المستخدم | قدرات Claude | الحساب والتكلفة | متى |
|---|---|---|---|---|
| **A. Claude Code** على جهاز المالك (CLI أو تطبيق سطح المكتب) + `.mcp.json` | محادثة Claude Code بالعربي، والأداة مفتوحة جنبها | كاملة: قراءة PDF بالرؤية، بحث ويب، مهارات (eda-regulatory)، أدوات المحرك | اشتراك Claude الحالي (حدود الباقة) | **M1، فورًا بعد خادم MCP** |
| **B. تطبيق Claude Desktop** + MCP | محادثة عادية مع رفع الملفات | رؤية + أدوات المحرك (بدون Bash/مهارات) | اشتراك Claude | M1 لغير التقنيين |
| **C. لوحة «المساعد» داخل الأداة** (Agent SDK كخدمة جانبية يشغّلها المحرك) | درج محادثة جوّه الأداة، أزرار اعتماد | قدرات Claude Code المدمجة + أدوات المحرك، مع hooks للاعتماد | **حساب API فقط** (مفتاح Console للشركة أو Bedrock/Vertex/Foundry). شروط Anthropic لا تسمح لتطبيق بتمرير طلبات مستخدميه عبر اشتراك Pro/Max أو رمز `setup-token`، ولا بعرض تسجيل دخول claude.ai (مُتحقَّق منه من صفحة legal-and-compliance ووثائق Agent SDK، 8 نوفمبر 2026) | M2 |
| **D. النسخة السحابية** (Managed Agents) | نفس اللوحة، والوكيل يعمل عند Anthropic | حلقة الوكيل مُدارة، جلسات طويلة، جدولة (مسح صلاحية الشهادات ليلًا)، «اشتغل حتى تمر المراجعة» | حساب API | M3 |

التوصية: ابدأ بـ A لأنه بلا تكلفة إضافية وبكامل قدراتي، وهو نفس ما جرى اليوم يدويًا، لكنه يصبح أدوات مكتوبة بدل استدعاءات HTTP مرتجلة. ثم C عندما يُفتح حساب API للأداة.

**حقائق تقنية مُتحقَّق منها (وثائق code.claude.com، 8 نوفمبر 2026):**
- خادم MCP محلي يُوصَّل بـ Claude Code عبر `.mcp.json` في المشروع: `{"mcpServers": {"dossier": {"type": "stdio", "command": "python", "args": ["-m", "dossier_engine.mcp_server"], "env": {"DOSSIER_WORKSPACE": "${DOSSIER_WORKSPACE}"}}}}`، أو بأمر `claude mcp add --transport stdio dossier --scope project -- python -m dossier_engine.mcp_server`. أسماء الأدوات تصبح `mcp__dossier__<tool>`.
- Agent SDK (Python) يقبل نفس الخادم في `ClaudeAgentOptions(mcp_servers=…, allowed_tools=["mcp__dossier__*"])`، ويدعم خوادم MCP داخل العملية نفسها (`create_sdk_mcp_server` + `@tool`) فلا حاجة لعملية فرعية في اللوحة.
- نتيجة أداة يمكن أن تكون صورة: `{"type": "image", "data": "<base64>", "mimeType": "image/png"}` تصل إلى Claude كمدخل بصري (PNG/JPEG/GIF/WebP). هذا أساس `document_page_image`.
- الاعتماد البشري: hook على `PreToolUse` يرجع `permissionDecision: "ask" | "deny"` لأدوات بعينها (التصدير، التوقيع)؛ الرفض من أي hook يغلب السماح. حصر الأدوات بـ `tools=[…]` و`disallowed_tools=[…]`.
- البث إلى الواجهة عبر `include_partial_messages=True` و`ClaudeSDKClient`؛ الاستئناف بـ `resume=<session_id>` على نفس الجهاز.
- العلامة التجارية: لا يجوز استخدام «Claude Code» في اسم المنتج؛ المسموح «Powered by Claude».
- شكل إعداد تطبيق Claude Desktop (`claude_desktop_config.json`) لم يُتحقَّق منه بعد من الوثائق؛ الشكل الشائع هو نفسه بدون `type`.

## 6. الذاكرة والسياق

- المحرك هو الذاكرة. Claude يعمل على وحدة أو فتحة في المرة، ويكتب نتيجته فورًا عبر الأدوات؛ انقطاع الجلسة لا يفقد شيئًا.
- **قراءات مخزَّنة:** جدول `readings(doc_id, page, kind, text, json, model, created)` في المحرك يحفظ ما استخلصه Claude من كل صفحة (نص، جدول، حقول). القراءة التالية لنفس الصفحة لا تُعاد إلا بطلب.
- حجم الملف: Module 3 كامل قد يتجاوز 500 صفحة؛ حد الطلب الواحد في الـ API هو 600 صفحة أو 32 MB، والصفحة تكلف تقريبًا 1,500 إلى 3,000 رمز. لذلك تُقرأ المستندات مستندًا مستندًا، والمحرك يحتفظ بالخلاصة.
- محادثة كل ملف تُحفظ في المحرك (`conversations`) ليُستأنف العمل من حيث وقف، بأي مضيف.

## 7. الحواجز

1. **لا تخمين:** قاعدة الأداة نفسها تسري على Claude. ما لم يُقرأ يبقى فارغًا ومُعلَّمًا.
2. **الأدلة من طرف ثالث لا تُمَس:** القفل الموجود (E-LOCKED) ينطبق على أدوات Claude كما ينطبق على الواجهة.
3. **كل نتيجة من Claude في المراجعة «مؤقتة»** حتى يعتمدها إنسان (المسار موجود: `confirm/override/dismiss_ai`). التصدير محجوب مع نتائج مؤقتة غير مُقرَّة.
4. **اعتماد صريح** قبل التصدير والتوقيع وسحب الأدلة، عبر hook في الوكيل يفتح بطاقة اعتماد في الواجهة (أو سؤال في Claude Code).
5. **ميزانية لكل مهمة** (task budget) حتى لا تستهلك قراءة ملف كبير الباقة بلا حدود، وتقرير بالرموز المستهلكة لكل ملف.
6. **سجل تدقيق كامل** باسم `claude` مع السبب والصفحات المستند إليها، قابل للطباعة ضمن تقرير المراجعة.

## 8. سير العمل داخل الأداة

1. **الاستقبال:** المستخدم يسقط الملفات. المحرك يقرأ بالقواعد ويضع ما وجده. Claude يفتح كل مستند صفحة صفحة (`document_page_image`)، يملأ ما نقص عبر `data_put` و`profile_set`، ويضع كل ملف في فتحته عبر `document_upload` مع سبب الوضع. الدرج الحالي يعرض النتيجة للمراجعة.
2. **البناء:** Claude يطلب المولدات (`generate`) بمدخلات من البيانات، ويكتب التبريرات والخطابات التي ليست قوالب، وتُحفظ كمسودات «غير موقَّعة» كما هو معمول به.
3. **المراجعة:** المحرك يشغّل الفحوص الحتمية. Claude يأخذ الأسئلة المفتوحة واحدًا واحدًا مع أدلتها، يقرر بسبب، ويكتب الرد المقترح؛ المستخدم يعتمد أو يعدّل. ثم `reassess` وخطاب النواقص من المحرك.
4. **التصدير:** المحرك فقط، بعد اعتماد المستخدم.

## 9. التكلفة والخصوصية

- **بالاشتراك (A وB):** ضمن حدود الباقة؛ قراءة ملف كامل بالرؤية تستهلك جزءًا ملموسًا من الحد اليومي، لذلك القراءات المخزَّنة مهمة.
- **بالـ API (C وD):** Claude Opus 5.5 بسعر 4 دولار لكل مليون رمز دخل و20 للخرج (وقت كتابة هذا). ملف 300 صفحة بالرؤية ≈ 0.5 إلى 0.9 مليون رمز دخل، أي قراءة أولى كاملة في حدود 5 دولارات، وتقل مع التخزين المؤقت للطلبات المتكررة.
- **الخصوصية:** في كل مسار فيه Claude تُرسل المستندات إلى Anthropic للاستدلال؛ احتفاظ 30 يومًا افتراضيًا في الـ API، ويمكن طلب عدم الاحتفاظ (ZDR) لحسابات الـ API المؤهلة. طبقة القواعد وحدها لا تُخرج شيئًا من الجهاز. القرار لكل فئة مستندات عند المالك، ويمكن وضع قائمة «لا يُرسل إلى Claude» في إعدادات الأداة.

## 11. المخاطر وما يقابلها

- **اعتماد زائد على Claude:** كل مخرجاته مؤقتة ومُعلَّمة بمصدرها؛ المحرك لا يقبل تصديرًا بنتائج غير مُقرَّة.
- **تكلفة غير متوقعة:** ميزانية لكل مهمة، قراءات مخزَّنة، وتقرير استهلاك لكل ملف.
- **اختلاف المضيفين:** سطح الأدوات واحد (MCP)؛ ما يعمل في Claude Code يعمل في اللوحة والسحابة.
- **تغيّر واجهات Anthropic:** الخادم يلفّ المحرك فقط؛ تبديل المضيف لا يمس المحرك.

## 12. قرارات مطلوبة من المالك

1. البدء بـ M1 (لا تكلفة إضافية، يومان).
2. لـ M2: فتح حساب API لدى Anthropic للأداة (أو Bedrock/Vertex/Foundry)، أو الاكتفاء بـ A وB على الاشتراك. استخدام الاشتراك داخل الأداة غير مسموح به بالشروط.
3. قائمة المستندات التي لا تُرسل إلى Claude أبدًا (إن وُجدت).
