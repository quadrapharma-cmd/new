# خطة أداة بناء ملفات CTD / eCTD لهيئة الدواء المصرية — مسودة 1 (06/11/2026)

**الحالة:** خطة بس، ولسه مفيش كود. مبنية على `CTD-KNOWLEDGE-BASE.md` و`ECTD-KNOWLEDGE-BASE.md` و`checklist/EDA-eCTD-Company-Checklist.xlsx`.

## 1. الفكرة في سطر

الشركة بتدخّل **البيانات مرة واحدة** وبترفع **المستندات**. والأداة بتعمل خمس حاجات:

1. تعرف المطلوب حسب نوع المنتج.
2. تفحص كل ملف.
3. تعيد بناء أي مستند غير مطابق من مستندات الشركة.
4. ترتّب وتسمّي وتربط.
5. تطلّع **3 مخرجات من نفس البيانات:**
   - **(أ)** ملف CTD للـ One Submission الحالي.
   - **(ب)** eCTD 3.2.2 لما المسودة تتعتمد.
   - **(ج)** eCTD 4.0 لـ 2028.

## 2. قرارات معمارية (التوصية ومبرراتها)

| القرار | التوصية | السبب |
|---|---|---|
| مكان التشغيل | **تطبيق محلي على جهاز الشركة** (محرك بايثون + واجهة ويب على `localhost`، ويتغلّف بعدين كتطبيق ديسكتوب) | الملفات سرية جداً (DMF، وتركيبات، وأسعار). حجم الملف بيوصل لجيجابايتات. ومحتاجين أدوات PDF/OCR مش موجودة في المتصفح |
| ربطه بـ Drugbox | **منفصل دلوقتي، وفيه نقطة ربط بعدين** (حساب الشركة، والاشتراك المدفوع، وتبادل الملفات مع الشركاء) | CLAUDE.md بيمنع تعديل واجهة Drugbox المعتمدة، والأداة دي منتج مستقل |
| مصدر القواعد | **ملفات بيانات (YAML) لكل إرشاد بإصداره**، مش كود | لما الهيئة تنشر مواصفة الـ EG M1 أو تحدّث NP.CAPP.065، اللي يتغيّر ملف بيانات بس، مع الاستشهاد بالمصدر |
| التحقق | محرك قواعد مستقل بيستخدم معايير ICH، وقواعد المسودة المصرية، و**EU VC v8.2 كبديل مؤقت**، ومكتوب جنب كل قاعدة مصدرها | معايير التحقق المصرية لسه مش منشورة |
| المستندات العربية | قوالب **Word (docx)** تتحوّل PDF بـ LibreOffice | تشكيل الحروف العربية واتجاه النص بيطلع صح، والشركة تقدر تراجع وتعدّل قبل التوقيع |

## 3. نموذج البيانات (المصدر الوحيد)

```
Company ─┬─ Parties (MAH, manufacturers, packager, releaser, store)
         └─ Application (ملف واحد = تركيز واحد + شكل صيدلي واحد · UUID ثابت)
              ├─ Profile: I / G-Imp / G-Loc · new / re-reg · One / Rolling · Case 450 · toll / UL / bulk
              ├─ Product data (Annex I fields)
              ├─ APIs → API manufacturers (option CEP/DMF/PQ/Full · GMP address · LoA · CEP)
              ├─ Formula (unit + batch formulas per batch size) · Specs · Methods · Batches · Stability
              ├─ Requirements (generated from rule pack) ── each → Document slot
              ├─ Documents (file · origin: generated / company / third-party · checks · status · version)
              └─ Sequences (0000, 0001… · type · unit · related seq · leaf/CoU lifecycle · tracking table)
```

## 4. منطق الشغل (Pipeline)

1. **Profile → Requirements.** محرك القواعد بيقرا ملف بيانات NP.CAPP.065 v5 ودليل الـ Quality v2، ويطلّع قائمة المستندات المطلوبة بشروطها (نفس الـ 91 بند اللي في الـ Excel).
2. **Intake.** المستخدم بيرفع ملف ويختار القسم، أو الأداة تقترح القسم من اسم الملف ومحتواه.
3. **Technical checks**، على كل ملف:
   - إصدار الـ PDF؛
   - التشفير والحماية؛
   - النص قابل للبحث؛
   - الخطوط مضمّنة؛
   - الـ bookmarks؛
   - اسم الملف أقل من 64 حرف، والمسار أقل من 180.
4. **Content checks** (فحوص التطابق):
   - قراءة النص والمقارنة بالبيانات: أسماء المصنّعين والعناوين مقابل الـ GMP والـ CPP، والتركيب، وأرقام التشغيلات، والمواصفات مقابل التحليل.
   - بند NP.CAPP.040 التلقائي: نتائج رقمية مش «Conform»، وQ للذوبان، وعمود المرجع الدستوري، وتشغيلتين على الأقل.
5. **Decision لكل مستند غير مطابق** (السياسة الثابتة):
   - **مستند بتنشئه الأداة أو مستند شركة** → إعادة بناء كاملة من البيانات، ثم Word للمراجعة، ثم توقيع وختم ومسح ضوئي، ثم رفع.
   - **علمي** → الأداة تبني الهيكل والجداول، وتطلب البيانات الخام الناقصة بالاسم.
   - **جهة تالتة أو أصل موقّع** → **ممنوع تعديل المحتوى**. الأداة تعمل الإصلاح الفني اللي ما بيغيّرش المحتوى، أو تطلّع خطاب طلب للجهة اللي أصدرته.
6. **Generation:**
   - Annex I، وإقرار التركيب، وحساب الملح، وتعهدات الـ CEP والثبات، وإقرار الترجمة؛
   - خطاب التغطية وجدول التتبع؛
   - جداول Module 3، وملخصات 3.2.R.2، والـ QOS (للمبتكر).
7. **Publishing**، بثلاث كتّاب على نفس البيانات:
   - **CTD One Submission:** فولدرات بترقيم NP.CAPP.065 (1.1.x / 1.2.x) وM3/M5. **ده اللي الهيئة بتستقبله فعلاً النهارده.**
   - **eCTD 3.2.2:**
     - أسماء ICH (Appendix 4، 379 مسار)؛
     - `index.xml` على الـ DTD، و`index-md5.txt`، و`m1/eg/` حسب المسودة؛
     - الـ `eg-regional.xml` بيتعمل على النموذج الأوروبي **ومكتوب عليه إنه مؤقت** لحد ما المواصفة تتنشر.
   - **eCTD 4.0:** `submissionunit.xml` (HL7 RPS)، وSHA-256، وأكواد الـ context of use، وإعادة استخدام المستندات بالـ UUID.
8. **Validation report:** Pass/Fail وBest Practice، وكل نتيجة بمصدرها، والتحقق على الـ DTD والـ XSD.
9. **Lifecycle:**
   - التسلسلات، والـ related sequence، والـ replace/delete؛
   - الـ baseline للملفات القديمة؛
   - التغييرات بفئات **PAC-N/A/B/II** وأقسامها من NP.CAPP.112؛
   - «current view» زي برامج المراجعة.

## 5. الشكل (Style) والشاشات

- **لغتين:** عربي (من اليمين للشمال) وإنجليزي، بمفتاح تبديل. أسماء أقسام الـ CTD والمصطلحات تفضل بالإنجليزي في اللغتين.
- **أسلوب «مكتب شؤون تنظيمية»:**
  - هادي، وكثيف المعلومات، وجداول واضحة؛
  - ألوان الحالة ثابتة في كل مكان: رمادي = لم يبدأ، أزرق = تم الاستلام، أخضر = مطابق، أحمر = غير مطابق، باهت = لا ينطبق؛
  - كل قاعدة أو ملاحظة جنبها **المصدر** (مثلاً NP.CAPP.065 §1.1.13) وتتفتح بضغطة.
- **الشاشات:**
  1. **لوحة الملفات:** كل ملف تسجيل، ونسبة جاهزيته، والناقص.
  2. **معالج المنتج:** خطوات (النوع، المنتج، الأطراف، المواد الفعالة، التشغيلات).
  3. **لوحة المتطلبات:** القائمة مقسّمة على الموديولات، ولكل بند حالة، وزرار «ارفع»، وزرار «ابنِ من جديد».
  4. **عارض المستند:** الملف، ونتيجة الفحص سطر سطر، وزرار إصلاح لكل مشكلة.
  5. **المولّد:** معاينة الخطاب بالعربي والإنجليزي قبل التصدير لـ Word.
  6. **البناء والتحقق:** اختيار المخرج (CTD أو eCTD 3.2.2 أو 4.0)، وتقرير التحقق، وتحميل الـ ZIP.
  7. **سجل التسلسلات:** شجرة الـ lifecycle وجدول التتبع.

## 6. ضمان الجودة

- كل قاعدة ليها اختبار ومصدر.
- اختبارات «ذهبية»:
  - أمثلة EMA السبعة لازم تتقرا وتعدّي على الـ DTD بتاعها؛
  - قالب ICH الفاضي لازم يطابق المسارات اللي الأداة بتولّدها؛
  - رسالة 4.0 لازم تعدّي على الـ XSD.
- ملف تجريبي كامل لمنتج وهمي (جنيس محلي أقراص مغلّفة) يتبني من أوله لآخره في كل إصدار.
- قاعدة ثابتة: **ممنوع وصف أي مخرج بإنه «مقبول من الهيئة»** قبل نشر معايير التحقق المصرية. اللي نقوله إنه «مطابق للمسودة وICH».

## 8. المخاطر

| الخطر | التعامل معه |
|---|---|
| مواصفة الـ EG M1 ومعايير التحقق مش منشورة | فصلها في ملف قواعد مؤقت، والكتابة للهيئة، وعدم الادعاء بالقبول |
| الهيئة تغيّر الإرشادات كتير | القواعد بيانات بإصدارات، وكل بند بمصدره وتاريخه |
| تعديل مستند جهة تالتة بالغلط | منع على مستوى المحرك: المستندات دي للقراءة بس، وأي تعديل بيترفض |
| حجم الملفات والـ OCR | معالجة محلية، وOCR بس للمستندات اللي محتاجاه |
| دقة النص العربي في الخطابات | قوالب Word، ومراجعة بشرية قبل التوقيع |

## 9. قرارات مطلوبة من صاحب المشروع

1. مكان التشغيل: محلي على جهاز الشركة (التوصية) ولا سحابة جوه Drugbox.
2. أول مخرج: CTD One Submission (التوصية، لأنه الشغّال النهارده) ولا eCTD على طول.
3. مستخدم واحد ولا فريق (مراجع ومعتمد).
4. هل الأداة للاستخدام الداخلي بس، ولا هتتباع للشركات.
